# Changelog

Notable changes to `tare.tools.os` are recorded here, newest first.

## Unreleased

- The publisher's test of who may publish no longer inherits `GITHUB_OUTPUT` from the CI runner: it failed there with `KeyError: 'tag'` and would have written into the test job's own outputs.
- Product releases are now signed with the project's key and published only after the signature verifies (ADR-075): the release workflow signs `bundle.zip` in a separate job that holds the key, uploads `bundle.zip.sig`, and `python install.py verify-signature bundle.zip bundle.zip.sig` checks a download by hand. Installed copies do not require the signature yet; a later release will make them refuse an unsigned one.
- AGY's Gemini 3.8 is not an alternative writer of heads-up notes after all: measured as the writer, it took a median of 76 seconds a call against 9 for Claude Sonnet, and a quarter of its calls failed, so its notes would arrive after you had already acted. The default is Claude Sonnet 5.5 at high reasoning, then Codex GPT-6.1 Sol.
- Heads-up notes are now written, by default, by Claude Sonnet 5.5 at high reasoning, with Codex GPT-6.1 Sol and then AGY's Gemini 3.8 as the alternatives when it is unavailable. Claude Haiku no longer stands in: when none of the three can answer, no note is written. `/routes` still changes the list and the level.
- A heads-up note you send to the agent now counts as confirmed only when the agent ran at least one step before answering. A reply that just agrees ("you are right, I will fix it") read as a confirmation; the record now keeps how many steps ran, and the calibration report shows those replies apart as agreed without checking.
- Heads-up notes now appear after a reply that follows delivered or attempted work (a delegated implementation, an edit the agent made itself, or a test or check that failed), and only now and then after other replies. The model that writes them is also told what tare is certain of, so it no longer says a change is in your project when it is only a kept candidate, and no longer predicts what tare will do next.
- When a reply needed a warning and tare showed no heads-up note, type `/missed` followed by what it should have told you (the words are optional): tare records that for the last finished reply, even while a turn is running, sends nothing to the agent, keeps it on this machine without any text in the log, and uses it with the note labels to tune when and what notes are written.
- Preparing two Works at once no longer pauses a sequence now and then with `failed to read .git/worktrees/workspace/commondir`. tare adds its Git worktrees one at a time per repository (parallel preparation, strict workspaces and challenger snapshots, across tare's own processes too); the lock is kept in tare's storage, not in the project. Two `git worktree add` running together could meet while the first had created that file and not yet written it.
- A heads-up note you rewrite in the composer still counts when you send it: keep the question's first line (`tare's heads-up after your last reply:`) and tare knows the message is about the note it last put in the composer, checks the agent's reply against the note as it was written, and keeps your version beside the original in the conversation's records.
- A heads-up note in the TUI now carries three buttons: **Ask the agent** only puts the note in the composer as a question you can edit (it keeps any draft and sends nothing), and **Useful** and **Not useful** record whether the note helped. A note counts as used only when you send it and the agent's reply confirms it; the records stay on this machine, without the note's text, to tune when notes are written.
- The backlog now records two delivered Ship items as done, with their evidence: the alert and shepherd lifecycle (#71) and the push preflight (#104). `backlog next` no longer offers them.
- The push hook's identity test now adds a changelog entry the changelog guard accepts on every platform. Its accepted case failed on Linux because the entry was too short; on Windows a line-ending rewrite hid that.
- The `pre-push` hook no longer fails a push that has nothing to send when a wrapper hook forwards its empty input as one empty line: the new identity check ran on an empty commit id.
- `tare ci pr` and the push hook now stop a push that would publish a personal email address. Before anything is pushed, `tare ci pr` reads the repository's settings and branch protection from GitHub; for a public repository (or one whose visibility it cannot read) it refuses when an unpublished commit's author or committer email is not a GitHub noreply address, names the commit and says how to fix it (set `git config user.email` to your noreply address and recreate the commit). The same check runs in the `pre-push` hook for every push, tags included, so pushes by hand are covered. It also refuses unsigned commits where the branch requires signing, and a repository whose settings leave no merge method. Auto-merge now uses a merge commit, or a squash when the repository forbids merge commits or requires linear history, never a rebase, and `tare ci pr` prints what it read under `preflight`.
- The console's `/usage` panel now opens on **Provider quota and credit**, its first row, before the conversation's own usage. It shows the saved readings at once and asks every provider again in the background (no model call, about 15 seconds); the row changes when the new reading lands. Reopening `/usage` reads again, so `tare quota` in a terminal is no longer needed for a fresh reading.
- Starting `tare` in a folder that contains tare's own history, such as the user's home folder, now ends at once with one line (`The workspace contains its history folder: … Choose a smaller workspace or a history folder outside it.`). It used to open the TUI and crash with a traceback while mounting; the check ran at start only when `--storage-root` was given.
- The console no longer fails a send with `[WinError 123] The filename, directory name, or volume label syntax is incorrect` when the **Workspace folder** field in Settings (F2) was left empty: an empty field now means the project that is open. F2 puts the cursor in that field with its text selected, so one stray key emptied it; the send then started the agent with an empty working directory, which Windows refuses.
- `tare quota` shows the two facts tare has about the OpenCode subscription, which reports nothing itself: until when a refused call left the plan out, and how many dollars of allowance tare's own sessions used in the last 5 hours, 7 days and 30 days (each reply's `allowance`, kept in the spend ledger when a session ends). It is not turned into a percentage left: OpenCode documents limits per model, but the refusal seen on 2026-11-09 stopped every paid model of the plan at once. Every subscription that a refused call left out now says so in `tare quota`.
- An API without a balance endpoint can have its balance stated: `tare quota --set ACCOUNT AMOUNT` (`openai-api`, `anthropic-api`, `gemini-api`, `bedrock`, `opencode-api`). `tare quota` and `/usage` then show that balance less the dollars tare's own sessions recorded on the account since. Each session adds the charge of its new calls to `<storage>/serve/provider-spend.jsonl` when it ends (a resumed session never adds a call twice; a subscription route adds nothing). It counts tare's use only, and routing does not act on it.
- The console's `/usage` panel shows what each provider last reported as left, in a last row **Provider quota and credit** (the saved readings of `tare quota`, with their time; opening the panel asks no provider). It replaces the line "Subscription balance: Unknown (not queried)", and `/tasks` points to `/usage` for it.
- A quota window that a provider reports at zero takes the routes it covers out of every selection until it resets, before a call fails: the selectors read `tare quota`'s saved readings through the same limit a failed call records. Only the covered routes leave (AGY's Gemini 4 Argon quota, its third-party group and its other Gemini models are separate; so is Claude's Fable window; a spent Codex window leaves the CLI and the native route), a window tare cannot place is never acted on, and a window with anything left changes nothing. The console and `tare serve` take the readings at start, after CLI discovery; tests never run a vendor CLI for it.
- New command `tare quota`: what each provider reports as left, read without a model call. Claude (`claude -p /usage`), Codex (`codex app-server`, `account/rateLimits/read`) and AGY (`agy -p /quota`) give each window of the subscription with the models it covers and its reset time, so a model with its own quota (Claude Fable, AGY's Gemini 4 Argon, AGY's third-party group) has its own line; OpenRouter gives its credit. A provider with no balance endpoint (OpenCode, OpenAI, Anthropic, Gemini, Bedrock) is listed as not reported, never guessed. The readings are saved in `<storage>/serve/provider-quota.json`. Until now tare learned that a plan was spent only when a call failed: on 2026-11-10 the first reading showed Codex spent until 12 November and AGY's Argon until 14 November.

It completed a typed audit in two calls and a typed plan in three through tare on 2026-11-10.
