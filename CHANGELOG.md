# Changelog

Notable changes to `tare.tools.os` are recorded here, newest first.

## Unreleased

- A route shipped `"qualified": false` (pin only) is used automatically once it answered on this machine: `native_routes.admission()`, which both the role ranking and the `/routes` matrix call, admits it when `tare setup --prove NAME` recorded a successful proof under the row's catalogue name and the route serves its vendor's own model (`vendor_models.origin_line`: a vendor CLI, a vendor API, AGY). A failed proof, a proof of another route of the same model (the CLI route for the API route) and a route with no line (a reseller, a local model) admit nothing; the proofs are read once per ranking, and with none recorded every result is unchanged. The matrix status line of such a pin-only cell now says "prove it once: tare setup --prove NAME". Gemini 4 Carbon on the Gemini API is the case that asked for it.
- /routes, Models per role: the column of the model owner's own API is now headed "Vendor API" instead of "API" (the owner asked why OpenRouter was a column apart from it: OpenRouter, Bedrock and the OpenCode API are resellers, and the origin and a reseller are switched separately). The source token in the profile is still `api`; only the label changed, in the table header, the bulk menu and the status line.
- /routes matrix: the two entries below this one are withdrawn ("never pretend to switch a route no entry can name" and "broad entries still cover nameless cells; no file reads on the UI thread"). They added a cell state, a round trip at every reload and a resolving context in `relay/environment.py` for one hand-made configuration: an inline role-table row with no model line whose id is also a catalogue name. That is declared as a known limit instead: such a row shows a cell, but an entry by its id names the catalogue's route, so unticking it stores nothing for the inline route (rename the row). The code of the tab and of `relay/environment.py` is as it was before those two entries; from them only two test changes are kept (the cross-vendor auditor test starts from the same-vendor line and checks that it goes; Save's answer is awaited for up to ten seconds).
- The Models per role tab of `/routes`, after the confirmation review of the entry below: (1) leaving a cell no entry can name out of a bulk action also left out the evidence that its broad entry was needed, so on a source whose only cell was such a route "every model off" stored nothing, and from `*@openrouter` off it removed the entry and switched the route on.
