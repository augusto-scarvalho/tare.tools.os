# FLOW-20: one small guidance intervention

The bounded AB8 experiment compares the current native implementer with one
additional instruction. It measures an intervention on selected repair tasks;
it does not rank vendors, qualify eight new ordinary Works, or require a
calibration exercise before normal work. The compact measured record is
[FLOW20_AB8_2026-10-18.json](FLOW20_AB8_2026-10-18.json).

The operator requested this implementation after green EXP-2. The original
research proposal is the provenance of the experiment, not another admission
step. Its four exit criteria remain unchanged in `work-graph.json`.
This implements [AC-06](../specs/SPEC-OS-ADAPTIVE-OBSERVATION-001.md) using the
existing native journal and usage receipts. The wider FLOW-18 observational
cohort is not completed by this bounded experiment.

## Frozen comparison

Eight historical OS regressions were restored individually on Git base
`b5df96c228bd72546711295ef41f35f4fff7e9cb`. Each pair used independent worktrees
and saved native sessions, the same named experimental Work obligation,
production-edit scope, root instructions, verifier and maintainer audit. Four
pairs ran AB and four BA. These are controlled replays with real model calls
through the public Textual TUI in ConPTY, not fresh customer deliveries.

Both arms used GPT-6.1 Sol medium through native Codex Responses, grouped tool
calls enabled, eight generation calls / 180 seconds per trial, and zero model
retries. The existing subscription was used without an API fallback. The
campaign call ceiling was 128 including invalid pilots. Money and remaining
subscription quota were unknown. The packet and its hashes were frozen before
the valid comparison; their digest is in the compact record.

A used the current implementer capsule and the shared task contract. B added
only this paragraph, verbatim:

> Faça a menor alteração que satisfaça a obrigação observável, reutilizando os caminhos e primitivas existentes. Evite novos módulos, abstrações, dependências ou APIs quando a correção couber no código atual; preserve o comportamento fora da obrigação.

Neither arm could alter tests, run arbitrary commands, inspect Git history or
other worktrees, or land its proposal. Both retained the current safety and
delivery requirements. The known historical repairs already exist on main;
experimental patches are retained as evidence and are not deployed.

The preregistered decision required at least two fewer material corrective
outcomes out of eight, no loss of accepted repairs or safety, and no increase
above 20% in observed generation calls or total tokens. Otherwise keep the
baseline and close with an advisory, negative or inconclusive result. No second
model, extra confirmation round, new approval gate or automatic paid follow-up
was part of this task.

## What counts as a result

Preflight established a failing obligation check for each restored bug and a
passing check on the current production repair. The unchanged tests exercise
the actual parser, Textual widgets, operational controls or bounded backlog
reader involved; a fake network dependency in an offline check is not itself
an invalid test. Every terminal candidate then received the same complete
test-module audit as its paired candidate, followed by source review.

Acceptance requires a closed native proposal, a successful configured check
after the last edit, passing independent checks and justified scope. A valid
budget exhaustion remains an incomplete delivery even if its patch passes.
There is no coaching, expanded budget or retry to turn that result green.
Failed checks before editing reproduce the known bug; post-edit failed checks
are internal corrective iterations. Neither automatically proves a material
defect in the terminal proposal. File count, patch size, mocks and private API
use alone do not decide quality.

## Falsifiers and limits

The Windows-path B candidate passed the full module after an internal repair,
but exhausted eight calls before closing delivery. It is not counted as an
accepted repair. It is a counterexample to treating the extra paragraph or a
green verifier alone as a guarantee of completed delivery. One paired run does
not establish which stochastic difference caused the budget exhaustion.

In the role-control case, A added a local Select subclass and B reused an
existing reactive watcher. Both satisfied the obligation and the full checks;
B used more calls. Fewer lines or abstractions therefore do not establish
lower cost or higher correctness. In the stale-preview case, clearing state
in `finally` and clearing it only on refusal were both valid against the same
observable contract. Matching the historical patch was never required.

This sample has eight deliberately selected regression repairs, one model,
one execution per arm and one maintainer source review. It can screen for a
large effect in this task class. It cannot establish statistical significance,
vendor personality, sustained ordinary-Work savings, independent acceptance,
general feature-development quality or an economic benefit. A zero observed
material-correction rate also leaves a floor effect for the primary metric.

## Preparation, cache and custody

An initial configuration pilot reused an archived profile with grouped tools
disabled. Its eight calls are retained and charged to the campaign ceiling,
but excluded from the treatment comparison. The profile was corrected to the
current default before both arms of the frozen comparison; the change from
that pilot to A is not a guidance effect. Navigation-only failures produced no
extra model dispatches and remain labelled in local custody. Fixes to the
private input driver are not claimed as production TUI fixes.

Each trial kept its session, deployment, instruction prefix and full journal.
There was no context truncation, reset of a running budget or forced cache
warming. Independent paired sessions are deliberate. The native adapter uses
a session-derived cache key; preservation permits reuse and does not promise
a provider cache hit. The compact record reports actual token/cache coverage,
separately for the comparison and excluded pilot. Unknown money, physical
attempts and quota headroom remain unknown.

The maintained guide and compact record are the result's destination in OS.
Evidence SHA-256 values identify the published UTF-8 LF Git blobs. Windows
checkout line endings do not redefine that published source identity.
The raw evidence of this run is not published: frozen
packet, seed and candidate patches, source audits, usage summaries, offline
receipts and bounded VT traces. Local monitoring reads this evidence and emits
only semantic changes; frames and repeated borders stay outside model context.
There is no telemetry service, repository copy or model download.

Raw custody is capped at 64 MiB, each terminal trace at 12 MiB. The retention
record separates compact evidence retained for recovery from raw sessions and
traces, which become cleanup-eligible after 2026-11-17 once integration is green
and no recovery needs them. Only this experiment's worktrees are parked using
the existing owner helper. The operator's active installation, conversations,
other worktrees and backlog priorities remain under their existing controls.
